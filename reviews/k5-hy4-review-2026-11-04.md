## 7. WHAT WAS MISSED

1. **The design doc’s build order contradicts its own unit table.** It says “Big Sort, with K-B and **2-C skins** first,” but 2-C is assigned **Fair Test Lab**. It also says Big Sort is “reused in five units,” while the built list uses it in **13**. Fix the table before using it as a build plan.

2. **The unit-assignment table lists all 23 units as if all engines exist.** Only Big Sort and Fair Test Lab are built. There is no visual **BUILT / PLANNED / STAND-IN** marker, so a developer can easily ship a config for an engine that does not exist.

3. **Fair Test Lab does not actually copy Mystery Machine’s key mechanic.** Unit 0’s Mystery Machine uses **limited trials**. Fair Test Lab forces every trial and has no trial budget, no “spend a trial” choice, and no cost for wasting one. Add limited trial tokens.

4. **Fact cards and question-unlocks disappeared.** The existing 6th–9th games use seeded levels, facts cards, and questions that unlock things. The two built K–5 engines have “Done,” “Play again,” and a slip count. Add one fact card and one unlock per engine or explicitly drop that site-wide pattern.

5. **Engine duplication is a maintenance hazard.** Inlining Big Sort into 13 pages and Fair Test Lab into 4 means one bug fix is 17 edits. The plan needs a build-time generator plus a hash check that all inlined copies are identical.

6. **CSS variables need fallbacks inside the shadow root.** `var(--surface)` with no fallback is fragile. If a page’s variables are renamed or missing, the game can become unreadable. Use `var(--surface, #fff)` etc.

7. **“Screen-reader and keyboard support is parked” is not compatible with “build real buttons now.”** Invalid `<button><ul>` content and no focus movement are structural. Fix them now; do not defer.

8. **K–2 “almost no reading” is not implemented in the configs.** K-B, K-C, 1-A, 1-B, 2-A, 2-B, and 2-C all have prompts or claim sentences that need a grown-up. No audio exists and browser speech is explicitly deferred. Add a visible “grown-up reads this” script or reduce to one-word labels with icons.

9. **Evidence is ephemeral.** The claim appears in the shadow root and disappears on reload. Teachers need a copyable/printable “What you found” line, especially for standards that require an argument, model, graph, or claim.

10. **The 60 text-free images are not wired to anything.** The activities use emoji. That conflicts with “clean and grown-up,” varies across Chromebooks, and leaves the generated-image inventory unused. Map images to cards first; keep short text labels for accessibility.

11. **Browser activities cannot earn real-action or real-observation verbs.** A small note is not enough. Pages need a prominent **“Offline step required”** banner for K-ESS3-3, K-ESS2-1, 1-ESS1-1/2, 2-LS2-1, 2-LS4-1, 5-PS1-2 measuring, 5-ESS1-2/5-PS2-1 arguing, and any “build and test” device task.

12. **“Unit 0 taught STRONG” cannot be detected by a static HTML file.** K2.0’s optional status is a teacher decision, not page logic. Do not try to branch by code; put the decision in the teacher note.

13. **Safety notes are split between unit text and activity notes, and the activity notes are thinner.** Coin cells, short circuits, warm lamps, water near Chromebooks, magnets, sand in eyes, tossing balls, litter gloves, and sealed fizzing bags need one shared safety-note component used by both the lesson and the game.

14. **A standards-verb audit was missing.** The earlier unit review checked mostly science content; several “Full” claims fail because the student product is sorting or reading provided data where the standard says plan/conduct, measure, observe at different times, or argue. This should be a separate acceptance test, not a prose review.
